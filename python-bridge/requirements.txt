# Exact pin list for python-bridge/venv (Python 3.11, CUDA-enabled — see
# README.md's "The venv" section for the full story of how this was
# resolved/verified). start.ps1 defaults to this venv; nothing here needs
# to be installed to just run the bridge if venv/ already exists.
#
# To rebuild the venv from scratch:
#   py -3.11 -m venv venv
#   venv\Scripts\python.exe -m pip install --no-deps --index-url https://download.pytorch.org/whl/cu130 torch==2.12.1+cu130 torchvision==0.27.1+cu130
#   venv\Scripts\python.exe -m pip install --no-deps -r requirements.txt
#
# Every install uses --no-deps with an exact version pinned here — this
# venv is dedicated to the bridge (not shared with another project like the
# old borrowed Debate venv was), so the corruption risk that discipline
# originally guarded against doesn't apply the same way here, but the
# hygiene is kept anyway: it's what makes this file a reliable, reproducible
# "this exact set of versions is known to work together" record rather than
# whatever pip's resolver picks on a given day. These versions were resolved
# once with normal (dependency-following) pip in a throwaway venv, verified
# working live against every model in local_models/, then transcribed here
# and reinstalled with --no-deps into the real venv — see README.md.
#
# torch/torchvision (installed separately above, from the CUDA wheel index,
# not plain PyPI):
#   torch==2.12.1+cu130
#   torchvision==0.27.1+cu130

# --- Phase 4: hearing (transcribe.py, vad.py) ---
# transcribe.py (Whisper turbo STT) needed zero new dependencies — it's the
# existing transformers/torch stack (WhisperForConditionalGeneration/
# WhisperProcessor), same as document_qa.py/image_caption.py.
#
# vad.py (Silero VAD) needed exactly one new dependency: onnxruntime, for
# the standard silero-vad ONNX release (see vad.py's module docstring for
# why the ONNX route was used instead of the pre-downloaded
# `Silero-VAD-v5-MLX` checkpoint, which turned out to be genuinely
# MLX-framework-specific weight layout, not just a repo-name label — and
# why the `silero-vad` PyPI package wasn't used either: it would pull in
# `torchaudio` just for its own WAV-loading helper, which this bridge
# doesn't need given local_models/audio_utils.py's own stdlib-only loader).
# CPU execution provider only (no `onnxruntime-gpu`) — live-benchmarked at
# ~250x real-time on CPU alone for this ~309K-param model, so GPU placement
# would add real complexity for no measurable benefit; see vad.py's module
# docstring. flatbuffers/protobuf are onnxruntime's own direct runtime
# dependencies (resolved once via normal pip dependency resolution in a
# throwaway venv, same recipe as every other pin in this file, then
# transcribed here and reinstalled with --no-deps).
